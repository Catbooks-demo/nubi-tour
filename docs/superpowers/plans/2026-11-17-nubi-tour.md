# 누비투어 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 실제로 운영되는 것처럼 동작하는 패키지여행 예약 사이트(손님 화면·직원 관리 화면·외부 API)를 만든다.

**Architecture:** Next.js App Router 한 앱이 손님 화면(`app/(site)`), 직원 화면(`app/admin`), 손님 API(`app/api/*`), 외부 API(`app/api/v1/*`)를 함께 낸다. 규칙은 DB를 모르는 순수 함수(`src/rules/*`)로, DB 작업은 서비스 모듈(`src/server/*`)로 나눈다. PostgreSQL + Prisma, 주기 작업은 앱 안 스케줄러가 advisory lock을 잡고 돈다.

**Tech Stack:** Node 22 LTS, Next.js(현재 안정 버전, App Router, TypeScript strict), React 19, Tailwind CSS, Prisma + PostgreSQL 16, zod, Vitest, Playwright, 토스페이먼츠 결제위젯 v2(테스트 키), Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-17-nubi-tour-design.md` (먼저 읽는다. 특히 "규칙"과 "세부 규칙")

## Global Constraints
- AXcellent용 주소·이벤트·규격·이름을 코드에 넣지 않는다. 이 사이트는 AXcellent를 모른다.
- 실제 여행사 이름·로고·문구 금지. 사업자등록번호 등 실제처럼 보이는 법적 번호를 지어내지 않는다. 푸터에 "시연용 가상 여행사입니다. 실제 여행 상품을 판매하지 않습니다."
- 공개 레포: 키·비밀번호·실제 내부 주소를 커밋하지 않는다. `.env.example`만.
- 토스 키가 `live_`로 시작하면 시작을 거부(오류 로그 후 종료). 키가 없으면 모의 결제(`method=mock`).
- 저장은 UTC, 날짜 계산·화면은 `Asia/Seoul`.
- DB 표·컬럼은 영어 snake_case(Prisma `@@map`/`@map`), 상태 값은 영어 코드:
  - 예약 `pending_deposit`·`pending_full`·`deposit_paid`·`fully_paid`·`completed`·`cancel_requested`·`cancelled`·`expired`
  - 출발일 `open`·`confirmed`·`closed`·`cancelled`·`departed`
  - 결제 종류 `deposit`·`balance`·`full`·`refund`, 수단 `toss`·`mock`
- 사용자 문구는 한국어 해요체.
- 테스트는 로컬에서 매번 돌리지 않는다. 각 작업은 브랜치 → PR(대상 `dev`) → GitHub CI 통과로 확인한다. `dev`·`main` 직접 push 금지. 테스트를 지우거나 약하게 만들지 않는다.

**Interfaces (Produces):**

- `paymentPlan(departureDate: string, at: Date, total: number, seats: number, depositPerPerson: number): {mode: 'deposit'|'full'|'closed'; firstAmount: number; payDeadline: Date; balanceDeadline: Date | null}` — 8일 이상: deposit, 24시간, 잔금 기한 = 출발 7일 전 KST 23:59:59; 7일 이내: full, min(24시간, 출발 전날 KST 23:59:59); 2일 이내(daysBefore ≤ 2): closed

- `departureStatus(d: {capacity, min_pax, seats_taken, paidSeats: number, current: string}): string` — `cancelled`·`departed`는 유지; seats_taken ≥ capacity → `closed`; paidSeats ≥ min_pax → `confirmed`; 아니면 `open`
- `canTransition(from: BookingStatus, to: BookingStatus): boolean` — 허용표: pending_deposit→deposit_paid|expired|cancelled, pending_full→fully_paid|expired|cancelled, deposit_paid→fully_paid|cancel_requested|cancelled, fully_paid→completed|cancel_requested|cancelled, cancel_requested→cancelled|(되돌리기: 직전 상태), 그 밖 거부

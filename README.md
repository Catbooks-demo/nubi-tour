# 누비투어

패키지여행 예약 사이트(시연용 가상 여행사). 손님 화면, 직원 관리 화면, 외부 시스템용 API를 갖춘 독립 서비스다.

- 설계: [docs/superpowers/specs/2026-11-17-nubi-tour-design.md](docs/superpowers/specs/2026-11-17-nubi-tour-design.md)
- 기본 브랜치 `dev`. `dev`·`main`에는 PR로만 올린다.

> 시연용 가상 여행사입니다. 실제 여행 상품을 팔지 않으며 결제는 테스트 모드로만 동작합니다.

## 만든 것

- 손님 화면: 상품 검색·출발일 달력, 예약(회원·비회원), 예약금·잔금 결제(토스 테스트 또는 모의), 취소 신청(국외여행 표준약관 수수료), 마이페이지, 고객센터
- 직원 화면 `/admin`: 대시보드, 예약·취소 승인, 상품·출발일, 문의 답변, 직원·API 키·작업 기록
- 외부 시스템용 API `/api/v1` (API 키, 개인정보 가림) — 설명 `/api/v1/openapi.json`
- 주기 작업: 결제 기한 만료, 출발 확정, 여행 완료, 잔금 안내

## 개발

```bash
cp .env.example .env            # DATABASE_URL을 로컬 PostgreSQL로
npm ci
npx prisma migrate deploy
npm run db:seed
npm run dev
```

시험: `npm test`(DB 필요), `npm run e2e`(빌드한 앱 + 시드). CI가 PR마다 web·e2e·docker 잡을 돌린다.

## 가상 예약 데이터 (AXcellent 연결 시험용)

누비투어에 실제 예약이 없어서, 공개 통계로 만든 가상 회원 4만 명이 각자 예약한 결과로 **지난 60일(예약한 날 기준)** 예약을 쌓고, 그 뒤로는 매일 같은 패턴으로 예약이 이어지게 한다. 설계는 "누비투어 가상 예약" 문서(2026-11-18)를 따른다: 여행자 유형 10개, 행선지 비중, 지역별 예약 시점(긴 꼬리), 요일·시간대, 추석 주 −25%, 연휴·성수기 출발, 10/20 중국 무비자 연장 트렌드(중화권 최고 ×2.1, ×1.3에서 멈춤, 동남아 −5%, 일본은 기간 내내 ×1.1).

예약·결제·취소·출발 처리는 서버 함수(`createBooking`, `mockPay`, `requestCancel`·`approveCancel`·`rejectCancel`, `cancelDeparture`, `runJobsOnce`)를 그 시각으로 그대로 부른다. 그래서 좌석·예약번호·수수료·상태가 실제 예약과 같은 규칙으로 맞는다. 예약금 규칙(1인 30만 원·24시간, 잔금 출발 7일 전까지)은 지금 그대로다.

```bash
npm run synth -- --dry-run        # 계획만 보기: DB·파일을 건드리지 않는다
npm run synth                     # 되채우기 (오늘 − 60일 ~ 지금)
npm run synth -- --replace        # 가상 데이터만 지우고(한 트랜잭션) 다시 넣기
npm run synth:daily               # 매일 모드: 10분마다 그때까지 된 몫 (--once: 한 차례만)
```

- 옵션: `--seed N`(기본 20261118, 같은 시드면 같은 회원·같은 계획), `--out DIR`(기본 `./synthetic-out`), `--force`.
- `DATABASE_URL`이 가리키는 DB에 쓴다. **되채우기 동안은 앱을 멈추거나 `JOBS_ENABLED=false`로** 둔다. 지난 시각으로 처리하는 동안 앱의 주기 작업이 지금 시각으로 끼어들면 결제 기한·출발 상태가 어긋난다(최근 15분 안에 주기 작업 기록이 있으면 멈춘다). 매일 모드는 앱과 같은 PC에서 앱을 켠 채로 돌린다.
- 결제는 모의 결제(`method=mock`)로만 넣는다. 생성기 프로세스에서는 토스 키를 비운다(앱 설정은 그대로).
- 지난 출발일: 시드는 오늘 + 3일부터만 출발일을 만들므로, 되채우기가 `prisma/seed-lib.ts`의 `planDepartures`(범위를 받게 함)로 오늘 − 57일 ~ 오늘 + 90일 출발일을 같은 규칙으로 만든다. 매일 모드는 날마다 오늘 + 90일까지 늘린다.
- 매일 모드는 상태 파일(`--out/daily_state.json`)로 이어 가서 다시 켜도 두 번 넣지 않는다. 6시간 넘게 늦은 계획 예약은 넣지 않고 "놓침"으로 센다. 하루가 끝나면 `--out/daily_answer_key.jsonl`에 그날 한 줄을 더한다.

**무엇이 가상인가 (표시)**

| 무엇 | 표시 |
| --- | --- |
| 가상 회원 | 이메일 `m00001@synth.nubi.test` ~ `m40000@…` (번호 = 가입 순서). 비밀번호는 아무도 모르는 값의 해시라 로그인할 수 없다 |
| 비회원 예약 | 예약자 이메일 `guest.<예약일>.<순번>@synth.nubi.test` |
| 가상 직원 | `ops@synth.nubi.test`(이름 "가상 운영 담당", 비활성). 취소 승인·거절, 최소 인원 미달 출발 취소, 문의 답변을 이 직원이 한다 |
| 예약에 딸린 것 | 위 예약의 여행자·결제·환불·취소·안내 문자·문의·후기, 가상 직원의 작업 기록 |

`--replace`는 `@synth.nubi.test` 예약·회원·직원과 그에 딸린 행만 지우고, 가상 예약이 잡고 있던 좌석을 되돌리고, 가상 직원이 취소한 출발일을 다시 연다. 상품·출발일 행은 지우지 않는다. 지난 시각으로 돌린 주기 작업 기록(`job_runs`)은 남기지 않는다.

**정답지는 로컬 전용**: `--out`의 `answer_key.json`(하루별 계획·트렌드 배수·주간 중화권·결과·"시작 구간 효과" 출발일 목록)과 `member_personas.csv`(회원별 유형)는 저장소·DB에 넣지 않는다. 기본 `synthetic-out/`은 `.gitignore`·`.dockerignore`에 있고, 저장소 안 다른 폴더를 `--out`으로 주면 멈춘다.

**시작 구간 효과**: 예약한 날이 기간 시작 전인 예약은 만들지 않는다. 그래서 기간 앞쪽(9월 말~10월) 출발일은 앞서 들어왔어야 할 예약이 빠져 좌석이 덜 차고 최소 인원 미달 취소가 실제보다 많다. 정답지 `start_effect`에 빠진 몫이 20% 넘는 출발일을 적어 두었으니 분석 확인 때는 빼고 본다.
